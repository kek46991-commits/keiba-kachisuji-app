# 許諾済みデータAPI 接続手順

## 目的

本書は、JRA・NARまたは正式なデータ提供事業者との契約後に、結果・払戻・オッズのAPIを安全に接続する手順を定めるものです。未許諾のWebページ、アプリ画面、非公開通信、個人契約データは対象外です。

## 接続前に受領するもの

| 項目 | 必須 | 確認内容 |
|---|---:|---|
| 契約・許諾根拠 | 必須 | 利用目的、DB保存、集計表示、保存期間、再配布条件 |
| API仕様書 | 必須 | エンドポイント、データ形式、レート制限、障害時仕様 |
| 認証方式 | 必須 | APIキー、OAuth、mTLSなど。値そのものはコード・CSV・チャットに保存しない |
| 提供データ範囲 | 必須 | 出馬表、確定着順、払戻、オッズ、更新頻度、対象主催者 |
| テスト環境 | 推奨 | サンドボックスまたは契約提供元が指定するテストデータ |

## 登録手順

1. 管理者が、提供元名・提供元キー・主催者・契約根拠・有効期限・提供形式を確認する。
2. 提供元を `authorized_data_sources` に `active` 状態で登録する。契約根拠が空欄の場合は有効化しない。
3. 認証情報は環境変数として登録し、アプリの画面・ログ・DBには保存しない。
4. API応答を提供元仕様に沿って検証し、未定義のフィールドや想定外のレコードは取込失敗として監査する。
5. 取込ごとに、提供元キー、契約根拠、取得件数、開始・終了時刻、結果、エラー概要を `data_import_audits` へ保存する。

## 定時取込の安全条件

定時取込は、提供元が更新頻度と自動取得を許可している場合だけ設定します。取込処理は、失敗が連続した場合やライセンス有効期限を超えた場合に停止し、過去の値を新しい値として表示しません。

| 制御 | 要件 |
|---|---|
| 許可リスト | `active` な提供元キーのみを実行対象にする |
| レート制限 | 契約仕様の上限より低い頻度で開始する |
| 重複防止 | 提供元のレコード識別子・発走日・レース番号を用いて冪等に更新する |
| 異常停止 | 認証失敗、形式不正、連続失敗、契約期限切れで停止する |
| 監査 | 実行ごとにデータ件数・ハッシュ・結果を記録する |
| 公開表示 | 契約で許可された集計・表示範囲だけを公開する |

## 実装開始の条件

以下がすべて揃うまでは、API接続と定時実行を開始しません。

- 提供元からの書面または契約上の利用許諾。
- API仕様書と認証方式。
- DB保存・戦略別精算・集計表示の可否。
- 自動取得の頻度とレート制限。
- テスト可能なデータまたはサンドボックス。
