# 公開サイト向け競馬データ契約：実行計画

更新日：2026-08-22  
対象サービス：**競馬でGO！**  
公開URL：`https://keibadego.manus.space`

## 結論

公開サイトへ実オッズ・結果・払戻を連携するには、**個人向けData Lab.／TARGETのデータを移さず**、対象データ、保存、内部処理、公開表示を明記した契約または書面許諾を取得する必要がある。

優先照会先は、地方競馬（ばんえいを除く）の出馬表、リアルタイムオッズ、確定後の結果・払戻をSports NaviにAPI提供した実績を公表し、B2Bデータ活用の問い合わせ窓口を用意する**Glad Cube／DRAGON DATA CENTER**とする。[1] [2] 次点として、JRAのデータベースAPIおよび中央競馬リアルタイムオッズAPIを案内する**Team-Nave**、JRAデータの商用利用照会の案内を掲載する**JRA-VAN**を並行して評価する。[3] [4]

## 照会・契約の進め方

| 順序 | 相手先 | 実施内容 | 判断基準 |
|---:|---|---|---|
| 1 | Glad Cube／DRAGON DATA CENTER | 準備済みの照会文面を使い、JRA・NARの対象範囲、DB保存、予想入力、結果精算、集計公開、費用を確認する。 | NARを含むデータの公開利用を、契約上明示できるか。 |
| 2 | Team-Nave | 既送信の照会に対する書面回答を待ち、HRDB-API／KeiBa-ODDS-APIのビジネス条件を確認する。 | JRAの結果・払戻・オッズを、保存・精算・公開集計まで許可できるか。NARの対象可否は別途確認する。 |
| 3 | JRA-VAN／JRA | JRA-VANの公式案内では、エンドユーザーへのデータ提供を伴う商用利用にはJRADBが必要であり、JRADBは法人契約に限定されるとされている。 | 現時点で個人運営のままJRADB契約はできない。法人化後のJRA向け候補として扱う。 |
| 4 | 契約候補の比較 | 書面回答をデータ範囲、公開可否、保存期間、料金、技術仕様で比較する。 | 要件を満たす候補だけを接続候補に残す。 |

## 契約で必須となる確認項目

| 分類 | 必須確認事項 |
|---|---|
| データ範囲 | JRA/NAR、競馬場、出馬表、結果、払戻、単勝・複勝・組合せオッズ、時系列オッズの対象可否 |
| 利用範囲 | API/CSV取得、DB保存、バックアップ、予想入力、結果精算、戦略別集計、公開画面表示の可否 |
| 公開条件 | 出典表記、表示遅延、個別データの転載可否、派生指標・集計値の公開可否、広告・将来の有料化への扱い |
| 技術条件 | 認証方式、テスト環境、IP制限、レート制限、エラー応答、障害連絡先、サービスレベル |
| 運用条件 | 保存期間、データ削除、契約終了時の措置、監査、利用停止・再開の手順 |
| 金銭条件 | 初期費用、月額・従量課金、最低契約期間、超過料金、サポート費用 |

## 公式情報で確認した制約

JRA-VANは、Data Lab.／JV-Linkの通常契約データをエンドユーザーへ配信するスマホアプリや商用サービスは、データの再配布・二次利用に当たり、通常契約だけでは実施できないと案内している。また、JRAの商業利用契約であるJRADBは法人契約に限られ、申込みには法人名と法人確認書類またはコーポレートメールアドレス等が必要とされる。[4] 従って、JRA側については、法人化前はTeam-Nave等の書面許諾を得られる別候補を確認し、法人化後はJRADBを再評価する。

NAR公式サイトは、掲載情報の権利が原則として主催者等に帰属し、事前許諾のない転載・複製を禁じている。[5] 公式閲覧ページを定期取得して公開サイトへ保存・表示する方法は採らず、NARまたは正規再提供事業者から、対象データの保存・派生集計・公開を明示的に許諾された契約だけを接続対象とする。NARは公式サイト上で所在地・代表電話を公開しているが、API契約窓口の公開は確認できないため、B2B候補からの提供可否を優先照会し、必要に応じて公式窓口へ契約相談の適切な部署を確認する。[6]

NARの公開調達情報には、地方競馬データ提供システム、次期オッズ等表示・映像伝送システム、統合競馬情報システム（IRIS）に関連するシステム構築・運用の記録がある。[7] これはデータ提供基盤が存在することを示すが、第三者へのCSV/API再提供、DB保存、公開サービス利用を許諾する事実を示すものではない。したがって、調達先・基盤運営者を無断でデータ源とみなさず、NARまたは契約上の再提供権限を有する事業者から、書面で利用範囲を確認する。

NAR公式の「ご意見・ご要望」フォームは、個別返信を基本的に行わず、営業目的の問い合わせを明確に断っている。[8] このため、同フォームからデータ利用契約を照会しない。NARの公式連絡先へ相談する場合は、代表電話でデータ利用・著作権許諾を扱う部署を確認するか、Glad Cube／DRAGON DATA CENTERなど、再提供権限の有無を契約で示せるB2B候補の書面回答を待つ。

## 許諾後の導入順序

提供元の書面または契約書を受領しても、その時点では実データ連携を開始しない。仕様書・認証情報・許諾範囲の照合を完了した後、以下の順序で導入する。

1. 許諾範囲をデータ種別、保存期間、公開粒度、更新頻度に分解して登録する。
2. 提供元をサイトの許可リストへ登録し、契約根拠と仕様書の版数を監査情報として保存する。
3. テストデータで、開催日、競馬場、レース番号、距離、コース、馬場状態、馬番を二重照合する。
4. 取込ごとに、ファイルまたは応答の識別情報、取得日時、件数、ハッシュ、成功・失敗を記録する。
5. 結果・払戻が確定したレースだけを戦略別の的中率・回収率に反映し、未確定データを補完しない。
6. 公式市場オッズを利用できるまでは、画面上の予想オッズと明確に区別する。
7. 取込失敗、認証失敗、レート超過、許諾範囲外の応答を検知した場合は、連携を自動停止し、管理画面で確認後にだけ再開する。

定時取込は、提供元が許容する更新頻度に限定する。高頻度のオッズ更新が許可される場合も、発走時刻が近い対象レースに絞り、実行履歴と停止条件を管理する。常駐タイマーではなく、サイト基盤の定時実行機構を利用する設計とする。

## 運営者が確定すべき情報

照会文面は準備済みだが、正式送信・契約申込みには次の情報が必要である。

| 必要情報 | 用途 |
|---|---|
| 運営主体の正式名称 | 契約者・請求先の特定 |
| 担当者氏名 | 問い合わせ窓口 |
| 連絡用メールアドレス・電話番号 | 見積・技術連絡・障害連絡 |
| 所在地 | 契約・請求情報 |
| 事業形態 | 個人、個人事業、法人化準備中、法人のいずれか |
| 公開予定の収益形態 | 無料、広告、将来の有料機能の予定を含めた商用利用審査 |

個人情報・会社情報を含むため、問い合わせフォームの送信、見積の同意、契約の締結は、内容を確認したうえで運営者の承認後に行う。

## 導入準備の検証状況

2026-08-22に既存の回帰テストを実行し、39テストファイル・113件がすべて通過した。許諾済み提供元の許可リスト、CSV取込監査、個人契約データの公開取込拒否、公式オッズ・組合せオッズの取込ガード、結果精算、買い目生成を含む既存の保護機構が稼働することを確認した。これは候補提供元との契約成立や実データの取込許諾を意味しない。書面許諾と仕様照合が完了するまで、実データの接続は開始しない。
