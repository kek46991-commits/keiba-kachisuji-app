# 公開サイト連携向けデータ利用契約：準備書

更新日：2026-08-22  
対象サービス：**競馬でGO！**（公開URL：`https://keibadego.manus.space`）

## 1. 契約の目的

本書は、公開Webアプリ「競馬でGO！」が、JRAおよび地方競馬（NAR）のレース情報を**提供元の許諾範囲内で**CSVまたはAPIにより取得し、予想の入力、結果精算、戦略別の集計表示に使用するための照会・契約準備書である。

個人契約のJRA-VAN Data Lab.、JV-Link、TARGET由来データは、公開サイトの取得元・保存元・表示元に一切使用しない。これらは個人PC内での分析に限定する。

## 2. 希望するデータ範囲

| データ区分 | JRA | NAR | 用途 | 更新希望 |
|---|---:|---:|---|---|
| 開催・レース基本情報 | 必要 | 必要 | 開催日、競馬場、レース番号、発走時刻、距離、コース、馬場状態の検証 | 開催前・変更時 |
| 出馬表 | 必要 | 必要 | 予想入力、馬番・騎手・枠番等の照合 | 開催前・変更時 |
| 確定着順 | 必要 | 必要 | 予想履歴への結果反映、的中判定 | 確定後 |
| 払戻 | 必要 | 必要 | 戦略別の確定収支・回収率計算 | 確定後 |
| 単勝・複勝オッズ履歴 | 希望 | 希望 | 推定値との比較、公開可能範囲でのオッズ変動分析 | 提供元の許容頻度内 |
| 組合せオッズ | 希望 | 希望 | トリガミ判定。ただし、許諾のある券種・頻度に限定 | 提供元の許容頻度内 |

> 個別の出馬表、払戻表、オッズ表を無断転載しない。公開対象は、契約が許容する範囲の予想結果、独自算出した指標、確定データに基づく戦略別集計値を原則とする。

## 3. 希望する利用範囲

| 項目 | 希望内容 | 契約で必ず確認する点 |
|---|---|---|
| 取得方法 | 認証付きCSVまたはサーバー間API | 認証方式、IP制限、レート制限、再試行条件 |
| DB保存 | 監査可能な形での保存 | 保存可否、保存期間、バックアップ・削除条件 |
| 内部処理 | 予想入力、着順照合、払戻精算、戦略別集計 | 派生データ・統計値の生成可否 |
| 公開表示 | 予想、独自スコア、的中率、回収率等の集計値 | 出典表記、遅延要件、表示可能な元データの粒度 |
| 商用利用 | 広告・課金導入の可能性を含む公開Webサービス | 営利利用、第三者提供、画面キャッシュ、二次利用の可否 |
| 運用 | 提供元の更新頻度に準拠した定時取込 | 障害時停止、利用停止時のデータ削除、監査対応 |

## 4. 技術・安全管理の説明

公開サイトでは、提供元を許可リスト方式で登録し、提供元識別子、利用許諾の根拠、ファイルハッシュ、取込日時、処理結果を監査記録として保存する。未登録のURL、出所不明のデータ、個人契約由来データは取込を拒否する。

API認証情報はサーバー側の環境変数で管理し、ブラウザおよび公開画面には配布しない。データに不整合、許諾外の利用範囲、認証失敗、想定外のレート制限が検知された場合は、取込を停止して監査ログに記録する。

高頻度更新は、発走時刻で対象を限定し、提供元が契約上許容する頻度だけで実施する。認可済みの仕様書を受領するまで、自動実行は有効化しない。

## 5. 契約先へ確認する質問

1. JRA・NARのどの主催者、競馬場、券種、データ種別を提供対象としますか。
2. CSVまたはAPIでの自動取得、DB保存、バックアップ、保持期間は許可されますか。
3. 予想モデルの入力、確定結果による精算、戦略別の的中率・回収率の集計に利用できますか。
4. 公開画面に、予想・独自指標・集計値を表示することは許可されますか。元データの画面表示に制約がある場合、許容される表示粒度と出典表記を提示してください。
5. オッズと組合せオッズは、利用できる券種、更新頻度、遅延、保存可否、公開可否にどのような制限がありますか。
6. 商用利用、広告掲載、将来の有料機能、第三者への再提供を含む場合の契約条件と費用を教えてください。
7. API仕様書、テスト環境、認証方法、IP制限、レート制限、障害連絡先、利用停止・削除の手順を提供できますか。

## 7. 候補別の優先順位

| 優先度 | 候補 | 理由 | 次の行動 |

| 2 | Team-Nave | HRDB-APIおよび中央競馬リアルタイムオッズAPIを案内している。 | 送信済み照会の書面回答を待ち、ビジネス利用条件とNAR対応を確認する。 |

## 8. 契約締結後の接続条件

1. 契約書または書面で、対象データ、保存、処理、公開表示の許諾範囲を確認する。
2. 仕様書に基づき、提供元をサイトの許可リストに登録する。
3. テストデータで、開催日・競馬場・レース番号・距離・馬場状態を二重照合する。
4. 取込後に保存内容を検証し、オッズ履歴と監査記録を確認する。
5. 正規データが確定するまで、公開画面では「予想オッズ」と公式市場オッズを明確に区別する。
6. 本番運用は、提供元の仕様に適合する定時取込、失敗時停止、再開承認、監査確認を備えた状態で開始する。
